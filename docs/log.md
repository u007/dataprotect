* **Update**: piiscrub — the race gate is green for the first time in a while, because it turned out nobody was running it. Three bounded-time tests each budgeted 5 s of wall clock: `TestLuhnRecognizeLongDigitRunIsBounded`, `TestLuhnRecognizeManyIBANsIsBounded` and `TestIPRecognizerLongMixedRunIsBounded`. Those budgets were tuned without the race detector, which multiplies the same work by roughly 5x to 11x, so all three failed under `-race` — measured 7.65 s, 5.87 s and 12.91 s against 1.16 s, 1.28 s and 1.21 s. The budget is now scaled 8x when the race build tag is set, through `boundedBudget` plus a per-package `raceEnabled` constant (`race_test.go` / `norace_test.go`), which leaves about 3x headroom on the slowest case. The inputs are deliberately left at full size: shrinking them would fit the budget but also let a superlinear scan finish inside it, and that growth rate is the property the tests exist to catch. The tests also stopped calling `t.Errorf` from a goroutine that can outlive the test — on a timeout that panics with "Log in goroutine after test has completed" — and now return the error on a buffered channel. The real gap was that `-race` was in no gate anyone ran: the root module had no `test-race` target, no Makefile rule and no CI workflow referenced the detector, so the three guards had never been run under instrumentation and their budgets had been tuned against an uninstrumented runtime that the tests never used.
