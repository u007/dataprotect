A working key corroborates the order of magnitude: NousResearch/hermes-agent issue #115356 reports `AQ.Ab8…` at 53 characters, 50 of body, used successfully against `generativelanguage.googleapis.com`. `bareShape` gained `AQ\.([0-9A-Za-z_\-]{35,})` next to the legacy `AIza` alternative, which stays because `AIza` keys keep working until September 2026. * **Update**: piiscrub — the race gate is green for the first time in a while, because it turned out nobody was running it. Three bounded-time tests each budgeted 5 s of wall clock: `TestLuhnRecognizeLongDigitRunIsBounded`, `TestLuhnRecognizeManyIBANsIsBounded` and `TestIPRecognizerLongMixedRunIsBounded`. Those budgets were tuned without the race detector, which multiplies the same work by roughly 5x to 11x, so all three failed under `-race` — measured 7.65 s, 5.87 s and 12.91 s against 1.16 s, 1.28 s and 1.21 s. The budget is now scaled 8x when the race build tag is set, through `boundedBudget` plus a per-package `raceEnabled` constant (`race_test.go` / `norace_test.go`), which leaves about 3x headroom on the slowest case. The inputs are deliberately left at full size: shrinking them would fit the budget but also let a superlinear scan finish inside it, and that growth rate is the property the tests exist to catch. The tests also stopped calling `t.Errorf` from a goroutine that can outlive the test — on a timeout that panics with "Log in goroutine after test has completed" — and now return the error on a buffered channel. The real gap was that `-race` was in no gate anyone ran: the root module had no `test-race` target, no Makefile rule and no CI workflow referenced the detector, so the three guards had never been run under instrumentation and their budgets had been tuned against an uninstrumented runtime that the tests never used. The target now exists and `make test-race` is green across the suite; AGENTS.md records that it is a correctness gate, not a speed gate ([concepts/development-conventions.md](/concepts/development-conventions.md), [README](../README.md))

* **Update**: piiscrub — `make fmt` was reporting `gofmt: clean` without running gofmt. The recipe called a bare `gofmt`, which is not on PATH here, so the substitution came back empty and the empty result was printed as clean; a format gate that passes when it cannot run is worse than no gate. It now resolves the binary from `$(go env GOROOT)/bin/gofmt` and fails with the path if it is missing. Verified by adding one space of misalignment to `recognizers/secret/secret.go`: the target now exits non-zero and names the file, then exits clean once the file is restored.

* **Update**: piiscrub — NLP sidecar shipped. `PERSON`, `ORGANIZATION` and `LOCATION` are new entity types (14 to 17), detected by the opt-in `recognizers/nlp.NLPRecognizer` client, which talks to a separate `sidecar/` module over HTTP (`/healthz`, `/v1/ner`, prose backend, 127.0.0.1:8787 by default). The root module stays standard-library-only and `NewScrubber()` stays env-free and deterministic; the caller wires the recognizer with `NewScrubberWithRecognizers` or `WithRecognizer`, and `PII_SCRUB_NLP_URL` is read by the caller. NLP entities carry confidence 0.85, so they fill gaps in prose rather than overriding the typed entities. NER cases live in an `integration`-tagged test, not in the golden seed, so the offline gate stays deterministic ([decisions/spec-v1.md](/decisions/spec-v1.md), [concepts/piiscrub-usage.md](/concepts/piiscrub-usage.md))
* **Update**: piiscrub — the sidecar no longer reloads the prose model per request. `prose.NewDocument` decodes the 17 MB model on every call when it is given no model, so the sidecar was paying 340 ms of model loading per request. The backend builds it once and passes it via `prose.UsingModel`: 352 ms to 19.6 ms per request, byte-identical output, race-tested. End to end, `Analyze` with the sidecar went from 338 ms to 19.6 ms (64x the regex-only path at 305 us) ([decisions/spec-v1.md](/decisions/spec-v1.md))
* **Update**: piiscrub — NER false positives on structured documents. The corpora showed the decoder reporting JSON keys, HTTP headers and spreadsheet field labels as names ("Record Number", "SameSite=Lax", "Path=/auth", "Medical Record Number"). Two rules fix the class: a span carrying a field-path character is a field, and a run whose LEADING words are two or more field names is a label. A fourth dataset file, `testdata/golden/ner/structured.json` (32 cases), now guards it — the first three sets were all prose and had a blind spot. NER detections on the nemotron corpus fell from 4.4 to 2.76 per text, on gretel from 6.6 to 5.90. Gate: typed P=0.8395 R=0.8718, span P=0.9012 R=0.9359 over 124 cases ([decisions/spec-v1.md](/decisions/spec-v1.md))
* **Update**: piiscrub — NER accuracy measured. `testdata/golden/ner/` and the `integration`-tagged gate `ner_accuracy_test.go` (run by `make test-ner`) score the sidecar's prose backend on two metrics: typed and span-level.
